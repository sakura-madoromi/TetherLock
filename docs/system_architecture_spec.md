# TetherLock 系统架构设计规范 (Design Specification)

- **项目名称**：TetherLock (牵绊锁盒 · 智能自律/社交陪伴玩具电子锁盒)
- **文档版本**：v1.1.0
- **更新日期**：2026-10-01
- **主控方案**：ESP32-C3 RISC-V + 1S 18650 锂电池供电
- **客户端方案**：Flutter 跨平台 App (Android / iOS / Desktop)
- **通信模式**：去中心化通用 MQTT 代理 + Ed25519 端到端加密签名 (E2EE)

---

## 1. 项目定位与核心需求

### 1.1 背景与玩法定位
* **玩法定位**：融合“自律打卡/防沉迷”与“极客潮玩/社交陪伴”，支持将物品锁入盒中，并将开锁与倒计时权限完全交由他人（朋友/伴侣/监督者）通过手机远程掌握。
* **物理防线策略（非破坏性安全）**：定位为 Toy 级产品，不考虑抵御暴力开箱工具（角磨机、电钻等）。但为防止“被锁者在自律崩溃时无痕作弊”，系统设计了**高心理门槛的单向物理破戒机制（易损断裂卡扣）**与**固件硬件级防反编译/防伪造体系**。
* **零维护服务器架构**：不依赖任何专有云服务或 Web 后台。全系统仅由“锁盒固件”和“Flutter 客户端”两个端点构成，通过任意公网/私有 MQTT Broker 实现消息透传。

## 2. 系统拓扑与安全信任模型

```
+------------------------------------+          +--------------------------------------+
| 掌管者手机端 (Flutter App)          |          | 智能锁盒 (ESP32-C3 固件)              |
|                                    |          |                                      |
| - 系统安全芯片保存 Ed25519 私钥     |          | - 内部固件写死受信任的公钥白名单       |
| - 状态监控面板 (电量/锁定/最后心跳) |          | - NVS 持久化存储防重放 Monotonic Counter |
| - 发起倒计时锁定 / 立即开锁指令    |          | - 内部硬件全封闭，外露 Type-C 仅供电  |
+-----------------+------------------+          +-------------------+------------------+
                  |                                                 ^
                  | (发布保留指令报文: command)                        | (定时1min静默轮询 /
                  | (接收状态心跳: status)                           |  按键主动查看)
                  v                                                 |
         +-------------------------------------------------------------------+
         | 通用 MQTT Broker (公共免费云 / 个人自建 Mosquitto / EMQX)          |
         | 作用：透明中继信箱，零业务逻辑，不存储私钥，不参与鉴权            |
         +-------------------------------------------------------------------+
```

### 2.1 端到端加密签名与防重放机制 (E2EE)
1. **密码学算法**：采用 **Ed25519 (EdDSA)**。
   * 签名私钥仅存在于授权者的手机系统安全芯片（Android Keystore / iOS Keychain）中；
   * 锁盒固件中硬编码信任的公钥列表（32 字节 Hex），签名验证耗时小于 10ms。
2. **防重放机制（单调递增计数器 Monotonic Counter）**：
   * 锁盒在内部 NVS Flash 中维护一个 `last_counter`（64位无符号整型）；
   * 指令报文签名载荷中必须包含 `counter`，且满足 `counter > last_counter`；
   * 即使网络报文被完全截获，旧的开锁指令也无法再次使用。
3. **零信任网络**：
   * MQTT 传输层无需昂贵的 TLS 握手，直接走极轻量 TCP 端口（如 1883），省电且极速建立连接；
   * 即使 Broker 被劫持或中途报文被篡改，由于缺乏合法私钥，篡改指令必定验签失败。

### 3.2 关键电气选型与引脚分配

| 功能模块 | 选用器件 | 对应引脚 | 工作说明 |
| :--- | :--- | :--- | :--- |
| **主控** | ESP32-C3 (单核 RISC-V) | — | 运行 FreeRTOS 极简固件，负责深度睡眠与定时唤醒 |
| **显示** | 0.96 寸 I2C OLED (SSD1306) | GPIO4 (SDA), GPIO5 (SCL) | 128x64 分辨率，静默轮询时休眠，按键时点亮 |

| **舵机控制** | MG90S 9g 金属齿舵机 | GPIO6 (PWM), GPIO7 (MOS) | 开锁时输出 50Hz PWM，舵机从 0° 转动至 90° |

### 3.3 物理防作弊与防刷机隔离
* **接口物理隔离**：外部露出的 Type-C 接口在电路板上只连接 VBUS 和 GND。USB 数据线（D+/D-）悬空不接，彻底阻断利用外露 USB 口刷入修改版固件绕过锁定的可能；
* **内部封闭**：ESP32-C3 芯片、烧录引脚和电池全封闭在螺丝不可从外部拆卸的底仓内。

## 4. 物理结构与机械机构设计

### 4.1 箱体空间、分区与尺寸规格
整个盒子由 3D 打印制成，包含三个相互隔离的物理区域：
1. **尺寸规格（放大款，比标准手机大约 3cm 余量）**：
   * **整机外部总长宽高**：$240\text{mm} \times 120\text{mm} \times 55\text{mm}$；
   * **储物仓净内部空间**：$195\text{mm} \times 110\text{mm} \times 45\text{mm}$（对比 iPhone 16 Pro Max $163 \times 78\text{mm}$，长宽各余出约 32mm，不仅可轻松放厚手机壳大屏手机，还能堆叠零食或游戏卡带）；
   * **前置独立电气仓**：长 35mm，高 45mm，容纳 18650 电池、MG90S 舵机、ESP32-C3 板卡与屏幕按键。
2. **物品储物仓**：用于放置受控物品；
3. **独立电气仓**：位于右前端，装配固定全部在内部完成。合盖锁死后，外部完全没有任何可拆卸的紧固件；
4. **顶盖与转轴**：通过销轴与箱体连接，内侧设有高弹泡棉/微型弹簧，锁舌释放时自动将顶盖弹起 1~2 厘米。

### 4.2 燕尾滑槽与易损断裂卡扣 (Breakaway Latch)
为了解决“热熔铜螺母麻烦”、“AB 胶粘死损坏后无法清理更换”的痛点，结构采用**免工具、免胶水的燕尾滑槽结构**：

```
     [ 顶盖内侧一体成型燕尾滑槽 ]
       \                      /   <-- 倒梯形槽 (Dovetail)
     ============================
       /                      \   <-- 卡扣底座做成匹配的滑块
     +--------------------------+
     |   滑入卡紧底座           |
     |          v               |
     |   [ 预制 V 型折断颈部 ]  |   <-- 1.0mm 截面，PLA 材质
     |          v               |
     |        [ 锁钩 ]          |   <-- 受到舵机凸轮阻挡
     +--------------------------+
```

* **材质建议**：卡扣滑块使用普通 **PLA 耗材**（刚性脆裂特性良好）；
* **力学阻尼设计**：
  * V 型凹槽截面设计为 $1.0\text{mm} \times 8\text{mm}$；
  * **日常自律状态**：垂直拉力在 **5 ~ 8 kg** 时完全牢固、不脱钩；
  * **极端放弃/破戒状态**：双手用力掰开或使用硬币撬动（施力 > 12 kg），卡扣沿预制槽齐整折断，顶盖打开，**箱体结构与电气主控毫发无损**；
* **秒级复活**：打开盒子后，将断裂残存的滑块直接从燕尾槽中推出来丢弃，重新滑入一个新打印的卡扣（耗时 1 秒，0 螺丝，0 胶水）。

### 4.3 模块紧固与组装工艺 (M2 螺栓 + 锁紧槽 + 结构胶)
* **执行舵机高刚性紧固 (M2 螺钉 + 内嵌螺母槽)**：舵机属于承受动态力矩和撬锁拉力的核心部件，采用标准 **M2 × 12mm 杯头内六角螺栓 (DIN 912) + M2 六角螺母 (DIN 934)** 锁紧，底盒支柱预留 $+Y$ 方向滑入式六角螺母沉槽（对边 4.0mm，防转间隙 0.2mm，无需热熔工具或电烙铁）。
* **轻质模块固定 (AB 胶 / 3M VHB 胶)**：OLED 显示屏、Type-C 充电小板、18650 电池槽通过 3D 打印的定位凸台与限位槽，配合环氧树脂 AB 胶或 3M VHB 双面胶直接粘合，兼顾便捷性与抗震性。

## 5. 固件状态机与超低功耗工作流

### 5.1 运行模式与功耗账本

* **目标**：单节 2600mAh 18650 电池维持正常运行 **> 30 天**。
* **唤醒周期策略**：
  * **定时静默轮询（每 60 秒唤醒一次）**：屏幕完全不亮、蜂鸣器不发声、舵机断电；
  * **快速连接 Wi-Fi**：利用 RTC 缓存的 BSSID、Wi-Fi 信道与静态 IP，握手时间控制在 **800ms ~ 1.2s**；
  * **MQTT 同步**：连接 Broker 并拉取保留指令报文，耗时约 **300ms**；
  * **单次能耗**：每次静默唤醒总时长约 1.5 秒，综合发射电流约 100mA，单次消耗约 **0.0416 mAh**；
  * **理论续航测算**：
    $$\text{每小时耗电} = 60 \times 0.0416\text{ mAh} + 0.015\text{ mA} \times 1\text{ h} \approx 2.51\text{ mAh}$$
    $$\text{总续航} = \frac{2600\text{ mAh}}{2.51\text{ mAh/h}} \approx 1035\text{ 小时} \approx \mathbf{43\text{ 天}}$$

### 5.2 状态机流程图

```
                       +----------------------+
                       | 长期态：Deep Sleep   |
                       | (~15μA 极低功耗维持) |
                       +----------+-----------+
                                  |
        +-------------------------+-------------------------+
        |                                                   |
  [ Timer 定时器 60s 唤醒 ]                        [ 用户按 GPIO9 唤醒键 ]
        |                                                   |
        v                                                   v
  [ 静默同步模式 ]                                  [ 主动交互模式 ]
  - 屏幕休眠保持不亮                                - 100ms 内点亮 OLED 显示 Loading
  - 不鸣叫蜂鸣器                                    - 采样电池电压显示电量图标
        |                                                   |
        +-------------------------+-------------------------+
```

## 6. MQTT 通信规范与自清理协议

### 6.1 命名空间与 Topic 定义
所有主题采用 `toylock/{box_id}/` 作为前缀，支持单 Broker 挂载多台设备：

1. **状态主题：`toylock/{box_id}/status`**
   * 方向：ESP32-C3 -> Broker / Flutter
   * 触发频率：每次唤醒发布一次（QoS 0，Retain = false）
   * Payload 示例：
     ```json
     {
       "box_id": "box_01",
       "counter": 12,
       "vbat_mv": 3940,
       "is_locked": true,
       "wake_cause": "timer",
       "rssi": -63
     }
     ```

2. **指令主题：`toylock/{box_id}/command`**
   * 方向：Flutter -> Broker -> ESP32-C3
   * 触发频率：控制者操作时发布（QoS 1，**Retain = true**）
   * Payload 示例：
     ```json
     {
       "box_id": "box_01",
       "counter": 13,
       "action": "unlock",
       "msg": "答应你的，开啦！",
       "sig": "3a8fbc...64字节Hex"
     }
     ```
   * **待签名原始数据（Canonical Payload）**：
     `"box_01|13|unlock|答应你的，开啦！"` 经 Ed25519 私钥签名生成 `sig`。

3. **保留消息“自清理”机制（Self-cleaning Retain）**：
   * 当 ESP32-C3 验签成功并驱动舵机开锁后，ESP32 立即向 `toylock/{box_id}/command` 发送一条 **Payload 为空（0 字节）且 Retain = true** 的报文；
   * MQTT Broker 按照规范将自动移除该 Retained 消息，防止下次唤醒时被重复触发。

## 7. Flutter 移动端架构设计

### 7.1 技术栈推荐
* **开发框架**：Flutter 3.x (Dart)
* **MQTT 客户端**：`mqtt_client` (支持 TCP/WebSocket 直连)
* **密码学库**：`cryptography` (原生支持高效 Ed25519 签名与公私钥派生)
* **安全存储**：`flutter_secure_storage` (与 Android Keystore / iOS Keychain 对接保存私钥)

### 7.2 核心界面与功能模块
1. **MQTT Broker 设置页**：允许填入自定义 Host、Port、Username、Password，默认可使用公共免费 Broker。
2. **锁盒管理卡片（多设备列表）**：
   * 展示所绑定的所有锁盒；
   * 显示当前锁盒在线状态（根据最后心跳时间计算）、电池电量进度条；
3. **控制仪表盘**：
   * **倒计时锁定**：选择时长并输入监督留言，点击后签名发送保留报文；
   * **一键开锁**：点击后直接调用本地安全私钥签名，发送开箱指令；
   * **公钥导出**：在给锁盒编译固件前，App 提供“一键复制公钥 Hex”功能，方便填入固件源码。

## 9. 异常处理与边界测试计划

### 9.1 容错与异常保护
* **弱网与 Wi-Fi 连接超时**：Wi-Fi 连接上限设为 5 秒。若超时未连上，保持锁定状态，静默模式立即休眠等待下个周期，按键模式在 OLED 显示 `Offline` 提示 5 秒后休眠；
* **低电量截止（Low Battery Cutoff）**：
  * 当 ADC 检测到电池电压低于 3.3V 时，屏幕闪烁 `Low Battery` 告警；
  * 系统停止定时 1 分钟周期唤醒，仅响应外部插线或物理按键，防止锂电池深度过放；
* **掉电应急开箱（电子保险）**：若电池彻底耗尽，外部直接插入 Type-C 充电宝，ESP32-C3 瞬间由外部 5V 经 LDO 供电启动，联网拉取指令正常开箱。

### 9.2 测试验证步骤
1. **密码学验签单元测试**：在 ESP32-C3 固件内预置测试密钥对与有效/篡改签名报文，验证 Monocypher 库验签耗时（<10ms）与正确性；
2. **整机底电流基准测试**：使用数字万用表（微安档）测量进入 Deep Sleep 后的整体静态电流，确认稳定在 15μA 以内；
3. **Flutter <-> ESP32-C3 连通性测试**：连接公共 MQTT Broker（如 `broker.emqx.io`），测试 App 签名发布后，ESP32-C3 是否能在 60 秒内准时执行开锁；
4. **燕尾槽卡扣破坏拉力测试**：组装打印件后，测量正常拉拽（5~8kg）下卡扣完好度，测试极限外力下（>12kg）卡扣是否齐整沿 V 槽断裂，并验证 1 秒无工具换新滑块。
